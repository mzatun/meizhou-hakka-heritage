### 1.2 核心诊断：为什么"有地图没故事"

对照 CBDB 仕途流场（有 5 万人物、4 万任官、时间窗动画的"数据深海"），当前梅州版的问题**不在渲染技术，而在数据层**：

1. **时间线节点太稀**：479→2026 共 12 节点，平均 130 年一个点，每点只有 1-2 句描述。南宋/元代/晚清整段空白（945→971→1052→1385 之间跳过了宋元 400 年、明清之间跳过了 1678 扩城、1849 修城、1859 太平军炸城等**最有故事性的节点**）。
2. **叙事是"标签式"而非"故事式"**：六维卡片每维一行文字（"農業為主，縣治初立"），没有人物、没有事件、没有冲突、没有因果链。CBDB 版的灵魂是"一个人从哪来、到哪去"，梅州版还没有"一个人"。
3. **已有数据未集成**：罗香林五次大迁徙数据（134 行 JSON，含路线/年代/规模/与梅州联系）已就绪但页面无迁徙模块；地标 10 个都有 `story` 字段但页面只显示名称；CBDB 只验证 3 人未批量抽取。
4. **桑基图是"手工估算"**：标注"待 CBDB 全量抽取后校準"，数据说服力弱。
5. **无"人"的维度**：没有人物卡、名人年表、任官路径、亲属谱系——而这正是故事地图最打动人的部分。

## 四、叙事架构升级建议（从"数据面板"到"故事地图"）

### 4.1 页面信息架构（新增 3 个 Tab）

```
Tab1 城市变迁（现状，深化）—— 时间线 + 六维卡片 + 坊巷故事卡
Tab2 人物流场（新增）★ —— 梅州人走向世界：人物 POI + 任官弧线 + 亲属谱系
Tab3 科举桑基（现状，换真实数据）—— d3-sankey 实证版

Tab5 侨乡南洋（新增）—— 松口→南洋弧线流场 + 侨批故事
```

### 4.2 关键叙事机制

1. **"故事卡"替代"一句话"**：每个时间节点/POI/人物的详情改为 3-5 段故事（起因→过程→影响→今址），配图（州志图、老照片、现场照）。
2. **人物→地点联动**：点击人物卡自动聚焦其故里 POI 并画出任官弧线；点击坊巷 POI 列出该坊科甲名录。
3. **迁徙动画**：罗香林五次大迁徙逐次播放（数据已含 route 经纬点），用现有城垣一样的"弧线动画"能力。
4. **时间线双轨**：主轨 = 政区/城垣（现状），次轨 = 事件/人物（新增），点击事件跳到地图对应位置。
5. **开篇叙事**（可选）：首页开场"一座城的千年"——从 483 程乡县到 2026 世界客都，自动播放城垣扩张动画（1052 土城 0.14km² → 2026 城区 60km²，urbanGrowth 数据已备好）。

### 4.3 视觉升级（参考 CBDB 仕途流场）

- 2D 地图：城垣扩张用**粒子流线**风格（贝塞尔弧线 + 移动粒子）画"下南洋"弧线

## 七、三个风险提示

1. **史实冲突需核实**：1385"扩城 985 丈"（现有数据）vs 1678"大水崩城扩至 985 丈"（嘉应古城兴替考）——必须查州志原文，故事地图的立身之本是史实可信。
2. **CBDB 许可边界**：教学免费可用；若产品化需注意授权（现有 docs 已标注）。
3. **别贪多**：优先级永远是 **城垣故事卡 + 人物层 + 迁徙集成**（数据已有），侨乡弧线和开篇动画放二期。
