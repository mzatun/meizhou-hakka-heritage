## 改了什么

1. **音乐外链**（原内联 base64 约 4.8MB → `assets/music.mp3` 3.78MB）。`new Audio("assets/music.mp3")`，双击打开即用（audio 标签不受 file:// 限制）。**若想再减 3MB+：把 mp3 压到 96-128kbps 或换短 loop，预计 500KB 内。**
2. **MapLibre 引擎外链**（原内联 1MB → `vendor/maplibre-gl.js` + `vendor/maplibre-gl.css`，BSD-3-Clause 许可，可商用）。
3. **删除 582KB 死代码**：原文件里 CHINA_JSON 省界数据内联了两份（615 行顶层一份、643 行引擎内一份），顶层那份从未被引用，已删。
4. **新增视口裁剪（LOD）**：`cullAll()` 在 moveend/zoomend 后只保留视野 ±200px 内的节点/POI/省名标记，其余 `display:none` 卸载渲染——参考站同款手法。用 display 而非 remove，点击/筛选/搜索逻辑不受影响；选中节点强制显示。
5. 文案同步："单文件内联" → "单文件+本地资产"（诚实描述架构）。

## 为什么数据不外链（重要设计决策）

数据（CHINA_JSON、路线、节点）保持内联，**不**学参考站用 `fetch("geo/*.json")` 外链——因为 `fetch` 在 `file://` 双击打开时会被浏览器 CORS 拦截，页面直接挂掉。而 `script/link/audio` 相对路径引用不受此限。**结论：双击即用的单文件交付，重资产用标签外链，数据必须内联。** 若未来部署到服务器（nginx/GitHub Pages），再迁移数据外链 + 懒加载，可进一步减到 ~200KB。
